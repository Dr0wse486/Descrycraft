Surveillance tools for Minecraft 1.21.1 + NeoForge — deployable remote cameras and a modular
recon drone. This README is about the drone, the reference implementation.

![The drone, four views](docs/drone-preview.png)

## Quick overview

- **Recon drone** — a flyable remote camera with a leash (shipped).
- **Planned** — pinhole cameras, a viewing terminal, motion sensors, tracking tags.
- **Design pillars** — one leash/signal model, one HUD (the "visor"), a modular workbench, server
  authority, assets generated by `tools/`.

## Features (the drone)

- One deployed drone per player.
- Remote piloting: first-person camera, HUD with position, range, hull and key hints.
- Signal model: the picture degrades with distance; 64 blocks of leash by default, extended by
  signal modules.
- Marking: creatures inside the scan cone with line of sight are marked by the server and drawn by
  the client.
- Modules: fitted at the Module Workbench (Recon Boost, Container Marker, Alert Radar, Signal, …).
- Battery: a pack is required for a usable picture — without one the view is snow and no module
  runs. Charge lives on the item.
- Attack: optional warhead (single use); blast and damage are validated and applied server-side.
- Client visuals: signal blur, HUD; shaders live in `assets/descrycraft/shaders/`.

## Default controls

- Right click a block — deploy the drone on that face
- Right click air / G — throw the drone
- Sneak + right click the drone — pack it back into the item
- Sneak + right click with a battery — install / remove the battery
- V — link / unlink (enter / leave the drone view)
- R — recall the drone
- W A S D / Space / Shift — flight
- C — roller (tap: one roll; hold: continuous spin)
- Sprint while piloting, with an Attack Module — charge attack
- X while piloting, with an Attack Module — detonate the warhead

Rebind under Options → Controls → Recon Drone.

## Commands

- `/descrycraft doorinteract [true|false]` — whether a pilot may open doors
- `/descrycraft dimension` — the recorded and current dimension, plus the recall guard's state

## Modules (summary)

At the bench: drone in the left slot, board in the middle, assembled drone out of the right.

- **Drone Customization Module** — opens the bay (required)
- **Recon Boost Module** — wider scan cone and range, and unlocks the boards that need it
- **Container Marker Module** — marks nearby containers
- **Alert Radar Module** — warns the owner about mobs and players
- **Signal Module I / II** — +32 blocks of leash each
- **Attack Module** — enables the charge attack and the warhead
- **Governor Removal Module** — raises the cruise ceiling

Prerequisites are enforced by the bench and by the server.

## Battery

- **Copper Battery** — 25% (about 12.5 minutes)
- **Graphite Battery** — 100% (about 50 minutes)
- Drain: 1% every 600 ticks, timed server-side

Charge lives on the ItemStack: it comes back with the drone on recall, and on being shot down.

## Networking and server authority

- Movement is client-driven, but the server validates it — ownership, per-tick step limit, leash,
  collision.
- Marking, container scanning, door interaction, the charge attack and damage are decided
  server-side. The client sends intent; the server decides and pushes the result to the owner.
- Module behaviour and sensor results are produced server-side and sent to the relevant player; the
  client only renders them.

## Assets and generation

- Most models and textures are generated by the Python scripts in `tools/` (standard library only).
- Shaders are hand-written, in `assets/descrycraft/shaders/` (post chain and fragment programs).
- Scripts worth knowing:
  - `tools/generate_drone_mesh.py` — OBJ/MTL and the manifest
  - `tools/prepare_drone_model.py` — converts a Blender export into project assets; see
    [`docs/model-pipeline.md`](docs/model-pipeline.md)
  - `tools/generate_textures.py` — PNGs (entity textures, icons, GUI)
  - `tools/verify_mesh.py`, `tools/verify_shaders.py` — validators
  - `tools/preview_*` — offline renders

Run the validators after changing a shader or a model.

## Build and development

Requires JDK 21.

```bash
./gradlew build         # build/libs/Descrycraft-<version>.jar
./gradlew runClient     # development client
./gradlew runServer     # development server
```

Asset pipeline:

```bash
python tools/verify_mesh.py
python tools/verify_shaders.py
python tools/preview_mesh.py    # build/preview/drone-preview.png
```

Updating the model or its textures:

```bash
python tools/prepare_drone_model.py <source> --install
python tools/generate_textures.py
```

## Project layout

- `src/main/java/dev/descrycraft/descrycraft/`
  - `entity/` — `ReconDroneEntity`, `DroneControlState`
  - `client/` — `DroneController`, `DroneHud`, `DroneSignal`, rendering and events
  - `item/` — `ReconDroneItem`, `DroneModuleItem`, `BatteryItem`
  - `block/`, `menu/`, `network/`, `command/`, `server/`, `registry/`
- `src/main/resources/assets/descrycraft/`
  - `models/entity/`, `shaders/post/`, `shaders/program/`, `textures/`, `lang/`
- `tools/` — asset generation (Python)
- `docs/` — design notes

## Where the tunables live

Most constants are in `entity/ReconDroneEntity.java` and the `client/` classes.

Common ones:

- `LINK_RANGE`, `SIGNAL_RANGE_PER_TIER`
- `SCAN_RANGE`, `SCAN_FOV`, `PING_RADIUS`
- `FLIGHT_SPEED`, `BATTERY_*`, `RECALL_TICKS`
- `MAX_HEALTH`, `CHARGE_*` (speed, damage, explosion radius, cooldown)
- client-side visual constants in `client/DroneSignal` and `client/DroneHud`

When adding a module, add its bit to `DroneModules.ALL` — otherwise it is stripped at deploy.
